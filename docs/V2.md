# Second iteration — maintainability, standardization, and reach

The first iteration asked "can this render a photograph properly?" and the answer is yes. This one asks a
different question: **can someone else maintain it, and can someone else use it?** New features are paused.
[`DESIGN.md`](DESIGN.md) stays the specification, [`ARCHITECTURE.md`](ARCHITECTURE.md) the map and
[`ROADMAP.md`](ROADMAP.md) the backlog; this page is the programme that reorders them.

*Written 2026-10-16. Everything numbered below was measured in this repository, not estimated.*

*Decided 2026-10-20: **Immich stays the library manager**, and the filesystem flavour stays an editor rather
than becoming a second library. Workstream B narrows to what that editor needs; see its own section.*

## What the measurements say, including where they contradict the brief

**The build is not the problem.** The brief named "rebuilding every shader every time" as the pain. That is
not what the clock says: touching `shaders/develop/exposure.wgsl` and rebuilding `sidecar-worker` takes
**1.6 s**, and `npm run generate` — which composes every browser shader *and* rebuilds the colour wasm — takes
**3.7 s** warm. `crates/shaders/build.rs` already emits a `rerun-if-changed` per file, so the dependency graph
is honest and cargo is doing the right thing.

What actually costs time is **coupling, not compilation**. Adding one slider touches seven or eight places
across four languages (ARCHITECTURE's own "Adding a develop control" checklist), and three of those steps fail
*silently* when forgotten:

- a new `shaders/client/*.wgsl` that is not added by hand to `WEB_ENTRIES` is simply never generated — the
  Vite build then fails on an unresolved import, and naga never validates the shader either;
- a wasm request struct without `#[serde(rename_all = "camelCase")]` reads every field as absent, so the
  feature does nothing, everywhere, with no error;
- `npm run check` passes against a stale wasm and stale composed WGSL, so the editor runs old code against
  new TypeScript.

Those are the maintainability target. A trap that a test cannot catch is a trap that will be sprung by
whoever arrives next, and this codebase is explicitly written for whoever arrives next.

**The Immich tie is shallower than it feels.** Grepping for it finds ~120 references, and they sit almost
entirely in one crate:

| Where | References |
|---|---|
| `crates/api` (`immich.rs` is 148 lines; plus `resolve`, `lib`, `export`, `config`, `session`) | ~118 |
| `crates/worker`, `crates/sidecar` | 3 |
| `crates/engine`, `crates/color`, `crates/raw`, `crates/shaders`, `shaders/` — **the whole photo pipeline, ~35,000 lines** | **0** |

Better still, `resolve.rs` already degrades gracefully: its chain is *Immich checksum search → storage
template by date and name → Immich filename search → picker*, and `OpenQuery` already accepts a plain `path`.
Half of the non-Immich path exists; it has simply never been the configuration anyone runs.

**The formatter's one-time cost, at four widths.** The sources are hand-wrapped past what rustfmt will
reproduce, so the diff never reaches zero and the only question is how big a reflow to accept:

| `max_width` | diff lines |
|---|---|
| 100 (rustfmt's default) | 20,365 |
| 140 | 12,583 |
| 160 | 9,688 (559 hunks) |
| 200 | 7,012 |

Against ~41,000 lines of Rust. Even the gentlest setting rewrites about a sixth of the codebase, and it is
entirely mechanical.

## Workstream A — formatting and standardization

The point of a formatter is not beauty, it is that **nobody argues about it and no diff contains noise**. It
is also the cheapest of these workstreams and the one that makes the others readable.

1. **Adopt rustfmt**, in exactly one commit that changes nothing but formatting, with the body recording the
   chosen `max_width`. Add the commit's SHA to `.git-blame-ignore-revs` so `git blame` steps over it
   (`git config blame.ignoreRevsFile .git-blame-ignore-revs`, and GitHub honours the file automatically) —
   this is the step that stops a format migration costing you history.
2. **Gate it in CI** next to clippy, which already denies warnings.
3. **Turn the three silent traps into loud ones**, which is the standardization that matters:
   - derive `WEB_ENTRIES` from the directory rather than a hand-kept list, or fail the build when
     `shaders/client/` holds a file the list does not;
   - make the wasm request structs' camelCase a property a test asserts across all of them, rather than a
     convention each one re-states;
   - have `npm run check` depend on `generate`, so it cannot pass against stale artefacts.
4. **Generate the uniform mirrors instead of hand-writing them.** Fifteen `#[repr(C)]` structs are mirrored by
   hand in WGSL and checked by naga. The check is good and should stay; the *hand-mirroring* is the part worth
   deleting, by emitting the WGSL struct from the Rust definition. This is the largest single item in the
   workstream and the one that most reduces the cost of a new control.

## Workstream B — modularity: the editor's half, not the library's

**The owner's call, 2026-10-20, in two parts.** *Immich stays the library manager* — nothing here builds a
catalogue, and the Immich-backed flavour keeps albums, search, ratings and thumbnails because Immich is good
at it and there is no reason to rebuild it. *The filesystem flavour stays anyway*, because it serves use cases
that are not the owner's: open a RAW, edit it, have the sidecar land beside it, with no server and no library
at all.

So this workstream is not "Immich becomes one adapter among several". It is narrower, and it is the thing
Workstream C cannot start without: **what has to be true for the editor to run with no Immich behind it.**

**Reading the code first changed the shape of this.** "Decouple Immich" sounds like one seam; it is three,
and they want separating rather than being merged behind a single trait:

| Concern | Where | What a non-Immich answer looks like |
|---|---|---|
| **Library lookup** — find an original by checksum, name, date-and-name; map paths | `resolve.rs`, `config.rs` | A folder tree plus the storage template `sidecar-template` already renders |
| **Identity and auth** — who is this, and may they see it | `session.rs`, via Immich's `/users/me` and an API key | Single-user, or local accounts. Today `auth_required` *is* `immich.enabled()`, so a folder deployment has no auth story at all |
| **Export destination** — where a finished render goes | `export.rs`: upload, then stack with the RAW | Write beside the original, or to an output folder. `Destination::Device` already exists, so this seam is half-built |

Two of the three are already half-separated, which is why this is cheaper than it looks.

**Against the narrowed goal, most of that is already answered.** An editor opens a file; it does not search a
library:

- **Lookup** mostly falls away. `OpenQuery` already accepts a plain `path`, which is what a file association,
  a drag-and-drop, an *Open with* or a command-line argument hands over. The picker's name search
  (`sidecar_template::find_by_name`, #28) is for a *library* without Immich, not for an editor with the OS
  file picker beside it — so it stays closed on its branch, with its tests, until something actually asks.
- **Identity** falls away too: a single-user desktop app has no accounts. Workstream C's threat model answers
  it — bind to loopback, take an ephemeral port, require a per-launch token, never a cookie.
- **Export destination** is half-built already: `Destination::Device` exists, and writing beside the original
  is the same code path the sidecar writer uses.
- **Configuration is the one that genuinely has to be built**: `Root` without `immich_prefix`, and a config
  with no `[immich]` section at all. Today `auth_required` *is* `immich.enabled()`, which is why a folder
  deployment currently has no auth story rather than a simple one.

**And one item is maintainability wearing a modularity hat**, worth doing whether or not a second flavour ever
ships: `immich.enabled()` is `!self.base.is_empty()`, a stringly-typed flag checked in a dozen places. Making
it a type moves to Workstream A as **A5**, and it is what stops the next feature re-introducing the coupling
by accident.

The original, wider order — kept because it is what a catalogue-replacing answer would have needed:

1. **Lookup.** The abstraction over what `resolve.rs` actually needs, implemented twice — the Immich one
   (today's behaviour, moved wholesale) and a folder one. A seam with one implementation is a guess; with two
   it is a design. **Started:** `sidecar_template::find_by_name` fills the one step in the chain that had no
   answer but Immich's, since `resolve.rs` already falls back to the template and the picker but the picker's
   own search returns nothing without Immich.
2. **Replace `immich.enabled()` with the presence of an adapter** — *this is A5.* It is
   `!self.base.is_empty()` today — a stringly-typed flag checked in a dozen places. Making "is there an Immich"
   a type rather than a string test is the standardization half of the same change, and it is what stops the
   next feature re-introducing the coupling by accident.
3. **Configuration.** `Root` stops requiring `immich_prefix`; a config can declare a folder library with no
   Immich section at all.
4. **Identity and export destination**, in that order, once lookup proves the pattern.

Keep the Immich adapter first-class throughout. It is the owner's own setup and the reason the project
exists; this is about widening the base, not dropping a user.

This is the unlock for everything in Workstream C, and it is cheap precisely because the pipeline crates never
learned about Immich in the first place.

## Workstream C — reach: where else can this run?

The one rule — every develop module written once in WGSL, running in the browser and on the server — is what
makes this plausible at all. Two targets, very different costs.

**Linux (and macOS/Windows) desktop: close, and no longer waiting on anything.** It is already a Rust binary
that serves a web app and talks to a local GPU through wgpu/Vulkan. With the library configuration staying what
it is, a desktop build is: start the api and worker on a loopback port against the same Immich this server
already uses, and open the UI. Wrapping that in a window is optional and, if wanted, Tauri is
MIT/Apache-2.0 and so licence-compatible. The honest remaining work is packaging and first-run setup, not
rendering. **This is the cheapest large win in the whole plan.**

**iPhone: partly already true, and the rest is harder than it looks.** The editor is a PWA and Safari now has
WebGPU on Metal, which is the configuration DESIGN already assumes — so *a phone pointed at a Sidecar server*
works today. A **standalone** on-device app is a different proposition, and the blockers are not the renderer:

- `wgpu` → Metal and LibRaw (C++) both build for `aarch64-apple-ios`; `burn` runs on wgpu, so even the ML
  masks are not automatically out.
- **ExifTool is Perl**, and it is shelled out to for export metadata, AF points and HEIC auxiliary images.
  There is no Perl on iOS. Each use needs a native replacement or must be dropped on that platform.
- **The HEIC decoder is an external program** by deliberate licence design (libheif is LGPL-3.0 — see
  CLAUDE.md), and iOS will not run one. On iOS the system decoder is right there and is not LGPL, so this is
  an adapter, but it is a real one.
- **There is no filesystem library on iOS**; there is PhotoKit. That is a library implementation of its own —
  the one piece of Workstream B's argument that a standalone phone app would still have to answer.
- The full-resolution session buffer assumes server VRAM, which a phone does not have in the same quantities.

So the sequence is: *desktop → re-examine the phone*. The phone question stays open deliberately: a standalone
app needs native answers for ExifTool, HEIC and PhotoKit, and none of them gets cheaper by being decided now.

## Order of work

1. **A1–A2, rustfmt and its CI gate — done**, at `max_width = 100`. The width was chosen for merges rather
   than for looks: git is line-granular, so two branches touching different arguments of one wide call
   collide in the same hunk, where at 100 those arguments merge cleanly. With a stack of branches that each
   merge `main` back down, that is the difference between a conflict and no conflict, and the last stack cost
   a day to exactly that. The reflow is one commit, recorded in `.git-blame-ignore-revs`.
2. **A3–A5: the three silent traps, the generated uniform mirrors, and the Immich flag as a type.** They pay
   off per *new feature*, which is exactly what resumes after them.
3. **B's one real piece — a configuration with no Immich in it — then C, the desktop target.** The rest of B
   turned out to be already answered or not the editor's problem.
4. Features resume from ROADMAP afterwards, against a codebase that is cheaper to change.

## What this plan deliberately does not do

- It does not re-architect the renderer. The single-source WGSL rule works and is the reason a second platform
  is even arguable.
- It does not drop Immich, and since 2026-10-20 it does not replace it either: the second flavour is an
  editor, not a library.
- It does not promise an on-device iPhone app. It promises to find out honestly what one would cost, once the
  library seam makes the question answerable.
- It does not touch the licensing position, which is non-negotiable and already shapes the HEIC and ExifTool
  boundaries above.
